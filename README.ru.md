# Mnemosyne

Mnemosyne — мастерская, которая живёт внутри кластера Kubernetes. Её творцы,
композиторы и писатели, живут там непрерывно: каждый рождается, находит идеи,
проходит через эскизы и черновики, отдыхает, болеет, впадает в отчаяние и
в конце концов умирает — по настоящему календарю. Критики пишут о том, что
выпущено, летописец записывает то, что произошло.

Каждый артефакт этого процесса, законченный или нет (партитуры, черновики,
пометки на полях, записные книжки, рецензии, главы жизнеописаний), несёт часть
состояния кластера как зашифрованную резервную копию. Произведения и есть
бэкап: тот, у кого достаточно произведений и ключ владельца, восстановит
API-объекты кластера в новом кластере.

[English version](README.md)

Дистрибутив называется `mnemosyne-art`, Python-пакет — `mnemosyne`, утилита
командной строки — `mnemo`.

## Как это устроено

- Сенсор каждые 15 минут читает объекты, перечисленные в инвентаре чарта.
  Изменение становится ключевым кадром или дельтой в реестре мастерской.
  Каждая часть сжимается, запечатывается открытым ключом владельца и
  раскладывается фонтанным кодом на кадры.
- Каждый новый артефакт сразу несёт ожидающие кадры: в музыкальных решениях
  партитуры (динамика и другие детали, которыми владеет кодек) или в выборе
  между вариантами чтения текста. Следующие произведения продолжают часть,
  пока она не переживёт потерю 30% носителей.
- Мастерская пишет своим ключом: она может запечатать бэкап, но не может его
  открыть. Открывает его только закрытый ключ владельца, который в кластер
  никогда не попадает.
- Собственные объекты мастерской (Atelier, Artist, Opus, Review и другие
  записи `mnemosyne.art`) — носитель, а не содержимое бэкапа.
- Владелец настраивает только инфраструктуру: окно, ресурсы, ключи, модели,
  хранилище и инвентарь бэкапа. Настроек для идей, школ, настроений или планов
  нет: то, что делают творцы, — их собственное.

В мастерской работают только музыка и литература. Остальные искусства в
репозитории (живопись, архитектура, парфюмерия) — этюды.

## Требования

- Kubernetes 1.29 или новее, Helm 3.
- StorageClass по умолчанию или существующий claim в
  `addon.artifacts.existingClaim`. Том с работами — ReadWriteOnce.
- Образы controller и studio. Их собирает только Actions-workflow репозитория
  **Mnemosyne images** и кладёт в приватные
  `ghcr.io/tym83/mnemosyne-{controller,studio}`. Workflow выгружает два
  артефакта `digest-*` со значениями для Helm. Для скачивания нужен
  существующий `imagePullSecret`; чарт никогда не создаёт учётные данные реестра.
- Модель: внешний API (Anthropic или провайдер, совместимый с OpenAI) или
  собственный OpenAI-совместимый сервер в кластере.
- `mnemo` на машине владельца: `uv sync --locked`, затем `uv run mnemo ...`.

## Установка через Helm

### 1. Ключи

```sh
uv run mnemo keys new --output ./mnemosyne-keys
```

Команда пишет два сырых 32-байтовых ключа X25519 и печатает `ownerPublic` (hex):

- `owner.key` — ключ владельца. Хранить офлайн. Он нужен только для
  восстановления и это единственный способ прочитать бэкап: если он потерян,
  произведения больше не расшифровать.
- `atelier.key` — ключ мастерской. Кладётся в Secret в пространстве имён
  мастерской:

```sh
kubectl --context <ctx> create namespace mnemosyne
kubectl --context <ctx> -n mnemosyne create secret generic mnemosyne-atelier-key \
  --from-file=atelier.key=./mnemosyne-keys/atelier.key
```

Вместо Secret ключ мастерской можно доставить через Vault (KV v2), AWS KMS или
CSI-том; см. `addon.key` в [README чарта](charts/mnemosyne/README.md).

### 2. Значения

`owner.yaml` для внешнего API:

```yaml
addon:
  enabled: true
  imagePullSecrets: [{name: ghcr-pull}]
  mode: API
  window: {kind: continuous}
  key:
    ownerPublic: <hex, напечатанный mnemo keys new>
    secretName: mnemosyne-atelier-key
    secretKey: atelier.key
  env:
    - name: MNEMOSYNE_ANTHROPIC_KEY
      valueFrom: {secretKeyRef: {name: model-api, key: token}}
  gallery:
    enabled: true
    ingress:
      enabled: true
      className: nginx
      host: gallery.example.org
      tls: [{hosts: [gallery.example.org], secretName: gallery-tls}]
models:
  endpoints:
    api:
      backend: anthropic
      location: external
      base_url: https://api.anthropic.com/v1
      model: <имя модели>
      key_env: MNEMOSYNE_ANTHROPIC_KEY
      vision: true
      max_tokens: 32000
      timeout: 900
  roles:
    artist: [api]
    critic: [api]
    chronicler: [api]
    eye: [api]
```

Secret с ключом API (`model-api` выше) создаёт владелец; чарт только ссылается
на него через `addon.env`.

Для собственной модели укажите в endpoint OpenAI-совместимый сервер в кластере
(llama.cpp, vLLM, Ollama) и `mode: background` или `mode: GPU` вместе с
`addon.gpuResource` и соответствующим лимитом ресурса:

```yaml
models:
  endpoints:
    text: {backend: openai, location: cluster, base_url: http://llm.models.svc:8080/v1,
           model: <имя модели>, max_tokens: 8192, timeout: 1800}
    eye:  {backend: openai, location: cluster, base_url: http://vlm.models.svc:8081/v1,
           model: <модель со зрением>, vision: true}
  roles: {artist: [text], critic: [text], chronicler: [text], eye: [eye]}
```

Каждая роль получает список endpoint'ов, которые пробуются по порядку. См.
[config/models.example.yaml](config/models.example.yaml). В модели уходит
только художественный контекст, снимок кластера — никогда.

### 3. Окно

`addon.window.kind` задаёт, как живёт мастерская:

- `continuous`: один долгоживущий Deployment (`mnemo-life-*`) в реальном
  времени. Каждый живой творец работает в своём ритме; судьба (рождения,
  болезни, смерти) идёт по календарю; критики и летописец пишут, когда есть о
  чём писать; сенсор и носители работают всё время. Это основной режим.
- `night`, `weekends`, `idle`, `always`: одна Job на ночь внутри окна
  (`startHour`/`endHour` в `timeZone` или простаивающий кластер). С
  `mode: chamber` такие ночи не обращаются к моделям.

`addon.suspend: true` останавливает мастерскую (масштабирует Deployment жизни
до нуля, приостанавливает запущенные Job).

### 4. Установка

```sh
helm --kube-context <ctx> install mnemosyne charts/mnemosyne -n mnemosyne \
  -f digest-controller.yaml -f digest-studio.yaml -f owner.yaml
uv run mnemo status --namespace mnemosyne --context <ctx>
uv run mnemo works list --namespace mnemosyne --context <ctx>
```

Образы указываются только по digest; в чарте digest нет, и без него установка
падает.

### Галерея

С `addon.gallery.enabled` Deployment только для чтения показывает историю
мастерской как сайт: творцы, произведения с черновиками, партитурами и
переводами, раунды внутреннего критика, критики, жизнеописания, школы и их
манифесты, хронология и страница восстановления. Он монтирует том с работами
только на чтение, не имеет токена сервисного аккаунта и ключей и пересобирает
сайт каждые `addon.gallery.refreshSeconds` (по умолчанию 900). Открыть его
можно через `addon.gallery.ingress` (`className`, `host`, `annotations`, `tls`)
или port-forward. Том ReadWriteOnce, поэтому поды studio и жизни назначаются на
узел галереи.

### История, прожитая в другом месте

`mnemo history export` упаковывает историю мастерской (например, синтетический
год из `hack/year/run_year.py`); `addon.history.source` (HTTPS) и
`addon.history.sha256` один раз переносят её на том после установки.
Мастерская, которая уже живёт на томе, никогда не перезаписывается.
Используйте тот же ключ мастерской и открытый ключ владельца, с которыми была
сплетена история.

## Что попадает в бэкап

- **Объявленный инвентарь** (`addon.inventory`): каждая запись называет версию
  API, kind и ресурс. Без масок. По умолчанию: Namespaces, ConfigMaps,
  Services, ServiceAccounts, PersistentVolumeClaims, Deployments, StatefulSets,
  DaemonSets, NetworkPolicies, Ingresses, Roles, RoleBindings и
  CustomResourceDefinitions. Добавьте записи для других установленных API
  (экземпляры операторов, объекты бэкапов данных вроде Velero `Backup` как карта
  к данным); чарт генерирует RBAC только на чтение ровно этого списка.
  `addon.snapshotNamespace` ограничивает бэкап одним пространством имён.
- **CustomResourceDefinitions по ссылке**: имя, группа, kinds, scope,
  обслуживаемые версии и SHA-256 схемы, без самой схемы. Схему в новый кластер
  возвращает платформа, которая устанавливает этот тип.
- **Не попадают**: Secrets (если не включены `addon.includeSecrets: true` и
  явная запись Secret в инвентаре), содержимое томов и баз данных, облачные
  ресурсы, сертификаты control plane, собственные записи мастерской.

## Где мастерская хранит файлы

На томе с работами лежит `/works/<release>-atelier/`:

- `creators/<id>/<время>/` — папка на каждое произведение: записная книжка,
  эскизы, черновики, партитуры, пометки на полях и `woven/` (носители, сделанные
  из них);
- `woven/` — носители из текстов критиков и летописца;
- `ledger/` — реестр состояний кластера и их запечатанные кадры;
- `process/<sha256>.json` — полный процесс произведения (каждый ответ и план),
  когда его запись слишком велика для etcd; запись в Kubernetes хранит путь и
  хэш;
- `lineage.json`, `life.log` — жизнь мастерской и её журнал.

`helm uninstall` оставляет том с работами, Atelier и CRD.

## Восстановление в новый кластер

1. **Соберите сплетённые произведения.** Подходит любой уцелевший набор:
   партитуры (`.xml`, `.musicxml`), тома текстов (`*.variants.json`) и панели
   публики (`*.audience.json`). Всё остальное игнорируется, повреждённые файлы
   считаются потерянными. Из работающей мастерской:

   ```sh
   kubectl --context <old> -n mnemosyne get pods -l mnemosyne.art/atelier=mnemosyne-atelier
   uv run mnemo works export --pod <под жизни> --source /works/mnemosyne-atelier \
     --output ./works --namespace mnemosyne --context <old>
   ```

   Экспорт отказывается от символических ссылок и перезаписи и пишет манифест
   SHA-256. Копии, хранящиеся где-то ещё (скачанное из галереи, S3-зеркало
   ночных Job, любой архив), — такие же годные входные данные.

2. **Расшифруйте и проверьте**, не обращаясь к кластеру:

   ```sh
   uv run mnemo restore --works ./works --key ./mnemosyne-keys/owner.key \
     --output ./recovered --dry-run
   ```

   `python -m mnemosyne.restore` принимает те же аргументы. В выходной папке
   появляются `archive.tar.zst`, упорядоченный `manifests.yaml` и `report.json`
   (расшифрованные и отвергнутые файлы, полные снимки, восстановленный момент).
   Если ни один снимок ещё не полон, ошибка говорит, сколько кадров у каждого
   снимка есть и сколько нужно. `--at <время ISO>` восстанавливает самое новое
   полное состояние не позже этого момента.

3. **Установите платформу** в новый кластер: каждый компонент, который
   предоставляет упомянутые по ссылке CustomResourceDefinition (операторы,
   Cozystack и так далее). Восстановление не пишет определения типов: оно
   проверяет, что каждое есть, повторяет попытки и затем останавливается,
   перечислив те, которых всё ещё нет.

4. **Примените:**

   ```sh
   uv run mnemo restore --works ./works --key ./mnemosyne-keys/owner.key \
     --output ./recovered-apply --apply --kubeconfig ./new.kubeconfig --context <new>
   ```

   Объекты применяются через server-side apply (field manager
   `mnemosyne-restore`) по фазам: определения типов, пространства имён, прочие
   объекты уровня кластера, объекты в пространствах имён; каждая фаза
   повторяется, пока не разрешатся зависимости. Объекты, которые в новом
   кластере уже есть (созданные его control plane или релизами платформы),
   сохраняются, а не перезаписываются. PersistentVolumeClaims получают новые
   тома: привязка к старому тому отбрасывается. Ссылки на владельцев
   переводятся на новые UID. Повторный запуск идемпотентен; успешно применённое
   остаётся, если позже падает другой объект.

5. **Заново передайте секреты и данные**: Secret с ключом мастерской, ключи
   API моделей, image pull secrets, Secrets приложений; содержимое томов и баз
   данных — из их собственных бэкапов.

6. **Продолжите мастерскую** (по желанию): установите чарт в новый кластер с
   тем же ключом мастерской и `ownerPublic`. С пустым томом мастерская
   продолжает свою родословную из восстановленных записей Atelier, Artist и
   Biography.

Подробности и ограничения декодера — в
[src/mnemosyne/RESTORE.md](src/mnemosyne/RESTORE.md).

## Стоимость API моделей

Все вызовы моделей идут в endpoint'ы, которые настраивает владелец; счёт
выставляет провайдер. Что наблюдалось при разработке с моделями Anthropic
(большая модель для художника, меньшая для критиков):

- один вызов критика, читающего изображения страниц партитуры: около $0,30;
- одно произведение композитора с эскизом и тремя черновиками: около $7;
- первые две ночи четырёх творцов в кластере: учтено $5,48 (неудачные вызовы
  не считались).

В режиме `continuous` расходы растут с числом живых творцов и с тем, как часто
они работают (после каждого произведения творец отдыхает от десяти минут до
нескольких часов, в зависимости от собственного темперамента и сил), плюс
критики и летописец, когда появляется что-то новое. Одинаковые запросы
отвечаются из кэша в `/works/cache`.

Мастерская ведёт свой журнал расходов и бюджет. Укажите каждому endpoint'у цены
(`price_in`, `price_out`, доллары США за миллион токенов) в `models.endpoints`;
тогда каждый вызов записывается в `/works/<atelier>/spend.jsonl`.
`addon.budget` (доллары США в месяц, 0 — без лимита) заставляет творцов ждать
следующего месяца, когда бюджет потрачен. Лимит расходов у провайдера остаётся
полезной второй страховкой. Собственная модель не стоит денег за вызов, но
требует своих мощностей.

## Ограничения

- Бэкап содержит только API-объекты Kubernetes. Содержимое томов, базы данных,
  Secrets (по умолчанию), облачные ресурсы и сертификаты control plane
  нужно сохранять другими средствами.
- Состояние можно восстановить только после того, как достаточно произведений
  пронесли его кадры; до этого оно ожидает. Большие инвентари становятся
  полными дольше.
- Устойчивость к потерям проверяется не более чем на 10 000 комбинаций
  уцелевших носителей; выше этого предела утверждений об устойчивости нет.
- Восстановление сохраняет объекты, которые уже есть в целевом кластере, и не
  делает очистки, отката и восстановления данных томов. Поля, назначенные
  кластером, и значения API по умолчанию могут потребовать миграции на другом
  кластере.
- Потеря ключа владельца делает бэкап нечитаемым. Одного ключа мастерской
  для этого недостаточно.
- Том с работами — ReadWriteOnce; мастерская работает одной репликой.
- `helm upgrade` не применяет обновления CRD; применяйте
  `charts/mnemosyne/crds/mnemosyne.yaml` отдельно.
- Отказ или ошибка модели проваливают это произведение; это записывается в
  `life.log`, и творец переходит к следующему.
- Переводчик переводит иноязычные тексты только на русский.
- Интеграции с Vault, KMS и S3 не проверялись на живых сервисах.
